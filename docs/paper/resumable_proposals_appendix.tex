\section{Executable proposals before completed evaluation}
\label{app:resumable-proposals}
The reuse experiment motivates changing what must be completed before a
candidate can be considered. At a complete frontier belief, define one program
for each legal alternative: take that action at the current own/public history,
then follow the unchanged parent at every subsequent history. These programs
are executable immediately. Unlike a contingent optimized continuation, their
construction does not require finishing a search tree. All hidden worlds with
the same observable history receive the same action.

Each program and the shared parent reference have a persistent interval
evaluator. Completed terminal or certified outcome mass and unexpanded tasks
survive each work quantum. Candidates with upper bounds no greater than the
parent's lower bound are eliminated. The widest remaining relevant interval
receives the next quantum, with ties favoring the shared parent. The first
strict candidate-lower/parent-upper separation is adopted; this does not claim
to identify the best alternative. Every physical transition counts against
the same local and global allowances. The arrival-weighted guarantee in
Equation~\ref{eq:frontier-gain} is unchanged.

The representation restricts the policy family in exchange for cheaper
construction and resumable verification. It cannot dominate full contingent
optimization with unlimited computation. Its purpose is to verify useful
complete programs within a finite allowance. Eight focused tests cover
interrupted comparisons, both seats, independently evaluated interval values,
parent-default execution and full root-gain decomposition.

\subsection{Named learned continuations}
A more expressive complete candidate retains a frozen learned actor as its
continuation. The serialized program includes that actor's identity and an
explicit legal action at the local root. At every later history it executes
the named actor unless a legal public override applies. Even when its first
action equals the parent's, it is a different program: its later decisions
can change. The unchanged original parent remains the comparison reference.

An identity-bound registry dispatches evaluation, execution and independent
Python replay to the same actor. Legacy consumers reject the named fallback
rather than silently interpreting it as the original parent. Execution commits
to one adopted program on first frontier arrival. Twenty-two focused test
cases cover both seats, interrupted budgets, actor identities, same-root-action
but different-continuation programs, actual execution, exact terminal values
and full root-gain decomposition. Eight cases additionally establish identical
receipts and selections when the alternative registry is empty.

The smaller family adds the other frozen parent to the ordinary one-action
candidates. The larger family also adds assisted WP and Point. Each named
candidate uses its actor's own root action. Candidate order is ordinary
alternatives, other parent, WP, Point; the first strict comparison is adopted.
There is no training or hidden-information input. Nineteen reused sources
comprise the sixteen preceding development fixtures and fresh-comparison
misses 133, 216 and 241, now explicitly development data. Both families retain
the two-million global and 100,000 local transition limits. Advancement requires
at least one new positive source, retention of every baseline positive source,
and no decrease in total exact gain or gain per transition. This criterion is
frozen before the development run; it supplies no confirmatory inference.

All 38 saved programs pass independent prefix, adopted-pair and actual-suffix
checks. Both families improve seven sources, versus six for the imported
parent-default baseline. Each adds two positive sources but loses the same
previously positive six-draw case. The smaller family retains 70.57\% of total
exact gain for 3.60\% more transitions; the larger retains 47.30\% for 7.51\%
more transitions. Neither meets the frozen criterion, so neither advances to
fresh confirmation or replaces the default. Larger executable candidate sets
can expand local opportunity while distributing finite evaluation work less
effectively. This result separates representational feasibility from useful
budget allocation.

\subsection{Omitting redundant preparation}
The existing public outcome bounds can be checked before candidate
construction. If certified winning and losing mass cover an entire frontier
belief, every legal continuation has the same conditional value. No candidate
can improve on the parent there. Omit that comparison and record its public
key and covered masses; leave all unresolved comparisons unchanged. This
moves an existing policy-independent proof earlier in the computation,
avoiding root-action queries and program preparation. Thirteen tests cover
both seats, win/loss certificates, unresolved cases, ordinary and named
continuations, interrupted prefixes and independent full-root values.

A focused serial benchmark uses original fixture 2, selected because all
1,304 frontier nodes are already certified. For each candidate family, old/new
then new/old runs use fresh dynamics and action caches; model loading,
serialization and audits are outside timed planning. Mean planning times fall
from 5.363 to 2.216 seconds for parent-default proposals, 8.486 to 2.228 with
the other parent, and 16.314 to 2.242 with WP and Point added: reductions of
58.68\%, 73.75\% and 86.26\%. All twelve saved programs pass unchanged-policy
checks. Each run still uses 4,974 prefix transitions; each pruned run also
passes independent prefix verification and actual-suffix replay. This is a
special-case implementation gain, not a population latency or strength claim.

A separate four-fixture serial comparison reuses checked interval receipts
whose evaluators have not advanced. It selects the first fixture in each
parent/five-or-six-draw stratum and uses the same counterbalanced order.
All sixteen saved programs have identical receipts, selections, prefix
worlds and physical work. Total times are 110.613 seconds for the original
implementation and 112.427 for the reuse implementation, a 1.64\% increase.
No speedup is established. The latter also performs the named-program
adapter's identity checks, so this is a net implementation comparison,
not an isolated cache microbenchmark. Evidence is in
\path{generated/frontier_timing_evidence.json} and
\path{docs/FRONTIER_TIMING_RESULTS.rst}.

Public-root pruning also precedes optimized proposal search, where it can
save physical transitions rather than only preparation. Nine tests verify
both-seat full-root values, saved work on certified examples and interrupted
budgets. On all eight original five-draw fixtures, the frozen comparison
reduces planning transitions from 10,826,089 to 10,688,461, saving 137,628
(1.2713\%). The 2,211 omitted comparisons account for exactly that work.
All 92 adopted programs, complete prefix beliefs and retained comparison
records remain identical. Four sources improve, with unchanged summed exact
increment $149393/113256000$; gain per transition rises by 1.2876\%.
The development efficiency criterion is met without a strength increase.

All eight saved programs pass independent prefix, adopted-pair and actual-tail
checks. Prefix and local oracles use 49,263 and 918,431 transitions; actual
suffixes execute and separately replay 96 transitions. Every realized point
and win-score difference is zero. Planning-time sums, 495.378 imported seconds
and 492.748 new seconds under concurrent execution, do not establish isolated
latency. No new match or training update is added.

The observed identity is not a universal budget-reallocation guarantee: other
roots may spend the freed allowance on later unresolved nodes. No fresh
strength claim is made from this unchanged-policy screen. The protocol,
independent exact reductions and retained-policy checks are indexed in
\path{docs/PRUNED_OPTIMIZED_FRONTIER_RESULTS.rst}.
