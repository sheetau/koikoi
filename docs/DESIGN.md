# Design and research decisions

## Objective

Build a reproducible Koi-Koi research system; exceed the published RL-WP baseline under its original rules, then evaluate a separately identified twelve-round variant. The scale requirement is at least 100 million complete twelve-round-format matches; its audited completion status is tracked in STATUS.md. Search simulations do not count toward that target.

## Architecture

- A readable Python reference engine is the correctness oracle.
- One allocation-free C++ transition core compiles as a CPU shared library and CUDA kernels. GPU state, observations, legal masks and rewards remain on device.
- NVRTC compiles CUDA kernels using the CUDA libraries supplied by PyTorch; no system-wide CUDA toolkit is required. CUDA Driver API launches kernels on PyTorch's current stream.
- A masked policy/value network sees only acting-player observations, public within-round history and match context. Optional opponent-card prediction uses hidden cards only as supervised labels.
- PPO with signed, player-relative returns is the initial training baseline. Multiple decisions by one player must NOT flip value signs. Round boundaries do not terminate match returns.
- PPO versus Q-boosting, flat versus explicit public features versus card-token networks, current versus archived opponents, belief versus uniform sampling, and search versus no search are separate experiments. The VRPO-inspired option and its deviations are documented in docs/VRPO.md; no improvement or equilibrium guarantee is presumed.
- Search samples consistent hidden states, then calls observation-only policies for both seats. No perfect-information optimization of sampled hidden states.
- The relational policy scores each card using shared weights over its encoding, same-month hand/field aggregates, and public global context. Compare it against the flat and Transformer policies; do not assume an architecture advantage.
- Public match-outcome dominance rules are an explicit inference wrapper, also applied to the published comparison opponent. Optional `endgame=true` training restricts the policy mask before action sampling and records the same mask for PPO; no off-policy post-sampling replacement occurs. Such checkpoints automatically retain this assistance in inference and search, with actual assistance settings in reports. The restriction preserves best attainable match outcome; it is disallowed for point-reward training. Simulator rules and rewards are unchanged.
- Search compares paired particle returns against the deployment policy's base action. The standard-error margin can reduce noisy action changes but does not remove critic bias or establish equilibrium or strength guarantees. Search remains disabled unless measured improvement justifies its cost.

## Optional fixed-history matchups

`opponent_fraction > 0` assigns the first floor(envs * fraction) environments to a single frozen checkpoint; the others retain current-policy self-play. The learner seat alternates by completed-match episode and environment index, remaining fixed through all rounds of a match. The opponent is sampled from its fixed masked policy, using only its own acting-player observation; it is not replaced during training. Profile and endgame assistance must match. This is a fixed historical-opponent mixture, not a full population scheduler, NFSP or an equilibrium solver.

Frozen decisions are excluded from the learner's PPO policy, entropy, belief and approximate-KL objectives, and from advantage-normalization statistics. The learner value head is trained on learner decisions. A separate trainable observation-only scalar critic estimates values from the frozen actor's perspective on opponent decisions; the frozen checkpoint's old self-play value is not used. Signed GAE still follows every simulator action, changing sign only when the acting player changes and resetting only at match termination. These are approximate observation-based critics, with the same partial-observation and truncation limitations as the baseline; no unbiased-return or equilibrium guarantee is asserted. Both trainable networks and Adam state are rolled back during graph preparation.

Track all simulator decisions and actual learner decisions separately. A fixed fraction of environments is not an exact fraction of completed matches or decisions, since match lengths differ. Frozen opponent weights/config/provenance are embedded in learner checkpoints, preserving restart without the original file. Loading an opponent preserves RNG. Opponent pretraining is a disclosed dependency, not added to the learner's initialization ancestry or twelve-round match count. The exported actor retains its original input/architecture and does not require the opponent or auxiliary critic at inference. Default fraction zero preserves ordinary self-play.

## Optional separate PPO return critic

`ppo_value=shared` retains the default algorithm. `observation` and `privileged` use a separate scalar MLP, 656 -> critic_width -> critic_width -> 1 with tanh hidden layers, for every GAE value and the rollout tail bootstrap. Both modes receive the original 560 observation features; the observation control pads 96 zeros and the privileged mode adds 48 opponent-hand indicators and 48 normalized remaining-stock ranks. This is the same training-only extension used by the Q estimator. Neither RNG state nor future-round deals are inputs. The dimensions, initial parameters and initialization RNG consumption are identical between controls. The output layer starts at zero; critic initialization preserves the actor sampling RNG.

The auxiliary critic has no shared parameters with the actor. The original actor/value model is unchanged and its observation-only value head continues to fit the same detached return target for deployment/search. Each value MSE receives value_weight, so introducing a return critic adds a loss, trainable parameters and changes joint gradient clipping relative to the shared baseline. Both controls use the same Adam, clipping and PPO minibatch schedule; critic_epochs applies only to Q-boosting. The critic_loss metric identifies the extra scalar loss under these configs. Hidden information influences learning targets and updates, never action selection inputs. This does not remove the actor's auxiliary value-learning gradients or claim isolated removal of shared-representation interference.

Current support is pure-self-play PPO; combining the option with Q-boosting or fixed opponents is rejected to avoid silently changing role semantics. Checkpoints embed critic weights and combined optimizer state. CUDA graph rollback includes both networks, and inference/export loads only the existing actor model. Both value conditions require finite-history and function-approximation caveats: the history-state critic theory motivating the screen does not establish unbiased clipped PPO here. Compare the two separate critics at matched decision budgets, then compare their results with the original shared-critic control; independent confirmation and final held-out evaluation remain necessary.

## Optional koi-only adaptation

`policy_scope=all` and `koi_width=0` preserve the original actor and update path. With `policy_scope=koi`, freeze all actor parameters except the two-output koi head, observation-only value head and optional koi residual branch. By default, the fixed card policy is sampled on card actions for both players during self-play. Optional `deterministic_cards=true` executes its legal argmax for both players instead; koi actions remain sampled. This flag requires koi-only optimization so there is no policy-gradient update from deterministic card actions. For either fixed card-selection setting, subsequent updates do not change the card action distribution at a given observation; trajectories can change because koi decisions change. The value head continues to fit returns on all decision phases, using its frozen shared representation.

This mode requires pure-self-play match PPO with a separate observation-only return critic and no belief loss. Reject fixed-opponent, Q-boosting, privileged-critic and round-reward combinations. The separate critic remains trainable on every decision and supplies GAE/tail values. Signed returns include all card decisions and all rounds; neither phase filtering nor koi decisions introduce new termination boundaries. Policy loss, entropy and approximate KL are averaged over koi rows only, and advantage normalization uses those rows' statistics. Empty koi minibatches contribute zero policy/entropy/KL terms with finite normalization; the ordinary Adam schedule still applies, including any existing momentum. Values share the optimizer and clipping with koi parameters.

`koi_width>0` adds an observation-only residual MLP: 560 -> koi_width -> koi_width -> 2, tanh hidden activations, added to the original koi logits. Its output layer starts at zero, preserving initial action probabilities; its initialization forks the CPU RNG so the baseline actor and sampling RNG are unchanged. Both the original koi head and residual branch can learn. The residual has no path to card logits or the value heads. A base actor can initialize this new branch; exact-width residual checkpoints can initialize or resume, while incompatible widths are rejected. The complete branch is available in ordinary, composite, frozen-opponent and search inference through the standard model loader.

Record `policy_decisions` for koi-only runs alongside all simulator decisions. All actions still belong to the learner's self-play policy, but only koi actions receive policy-gradient updates. The lineage budget continues to count all learner/simulator decisions; it does not invent missing historical phase counts. Comparisons hold simulator updates fixed, not the number of policy-gradient decisions. Full continuation versus head-only adaptation changes parameter freezing and policy normalization together; head-only versus residual adaptation tests added capacity under the same phase restriction. All three proposed controls use a fresh observation critic, so none is identical to ordinary shared-critic continuation.

For deterministic frozen cards, collection retains the usual random draw before replacing only card actions, and records behavior log-probability zero on those rows. Koi rows retain their sampled actions and original log probabilities. Card rows are already excluded from the PPO ratio, policy loss, entropy, KL and advantage normalization. All value targets and signed GAE still follow the actual full trajectories; no new termination or off-policy correction is introduced. Checkpoints retain the training flag and exact restart state. Inference action-selection flags remain separate, and default training remains sampled.

The motivation is the prior replicated MLP koi-substitution diagnostic and small positive koi-search development result. Neither proves that parameter sharing causes the observed deficit or that specialized self-play will improve public-baseline strength. The teacher's outputs are not training targets, no private observations enter inference, and the experiment does not alter the fixed search-replication or scale-training protocols.

## Evaluation

Seeded deals are indexed by match and round, independent of actions. A pair repeats the same seat-assigned deals and initial dealer with agent identities swapped. Confidence intervals resample independent pairs, not individual games. Final test seeds are disjoint from training and development seeds. Report draw-adjusted match win rate, point difference, latency and training budget. Match rewards are +1/0/-1 for win/draw/loss; optional round-point warmup must be labeled and disabled for final win-rate training.

Point difference in our reports means final candidate points minus final opponent points. With conserved total60 and initial30 each, this is twice the original paper's final-minus-initial statistic. Preserve report units; divide both means and interval endpoints by2 only when explicitly presenting the paper's convention. See COMPARATORS.md for the verified source and final secondary RL-Point comparison.

The original upstream model is evaluated on its eight-round, bankruptcy-ending rules. Its historical feature quirks must be preserved in the adapter, never silently repaired for published weights. Twelve-round transfer is a separate result.

Large deterministic checkpoint duels also run in native batches: duplicate the complete initial state, exchange agent seats, and freeze finished rows. No redealt episodes enter an evaluation pair. Check both devices/profiles against sequential reference duels and record batch shape/device, since floating-point near-ties can differ across execution paths. The native endgame guard reads only captured cards, scores, phase and public match context.

A diagnostic composite policy can substitute only koi/stop decisions, routing by public phase. Evaluate both directions against the same published opponent and paired deals to identify decision-specific weaknesses. Component identity and checkpoint budgets remain explicit; a composite result must not be attributed to the original checkpoint. Search is disabled for this diagnostic.

## Reproducibility

Checkpoint model, optimizer, RNG, simulator state, config, counters, code revision and source hashes. Atomic checkpoint replacement and JSONL metrics permit restart. Store generated artifacts under ignored runs/. Pin external sources and retain license notices. Code and experiment protocols are tracked; local agent instructions are ignored.

Exact resume preserves the experiment config and counters. Weight-only initialization creates fresh optimizer, RNG, simulator and counters and records the pretraining source separately. Paper8 pretraining never counts toward the research12 match requirement. Initialization lineage survives subsequent resumes.

Optional CUDA graphs capture fixed-size PPO minibatch updates and, independently, fixed-horizon PPO collection/return calculation. Counter bookkeeping stays outside capture. Rollout warmup restores simulator state and RNG before replay, and the graph retains the current model parameter addresses. Return a fresh batch dictionary so PPO normalization cannot replace the graph's stored output references. Explicit resume-time rollout capture preserves model/optimizer/simulator/RNG/counters and records the execution change. Warmup and capture effects on parameters, optimizer tensors and RNG are restored in place before the first real replay. Static tensor addresses and optimizer hyperparameters must stay fixed after capture. Graph-mode Adam uses capturable device-side counters; comparisons against eager execution use identical optimizer settings, while the older non-capturable mode can differ through rounding. See the [PyTorch 2.12 capture guidance](https://docs.pytorch.org/docs/2.12/notes/cuda.html#cuda-graphs).

Search has a separate optional CUDA capture path. Each cache entry is indexed by particle-branch batch size and profile, with persistent candidate-action and public root-sign input buffers. Only the tensor rollout is captured; hidden proposals, root decisions and confidence comparisons remain outside. Preparation restores sampled simulator state and CPU/CUDA RNG; current model parameter tensors are read on replay. Cached configuration, model object, device, horizon and particle count must remain fixed during a search agent's lifetime. Both deterministic and sampled policy rollouts preserve their common-randomness semantics. The same-player/other-player sign, endgame guard, terminal outcome retention and unfinished-tail bootstrap are unchanged. Report three executed warmup rollouts separately from logical search simulation; recording does not execute another rollout. No search transitions count toward training matches. First-use latency includes preparation. This is an execution optimization, not strength evidence or an equilibrium guarantee.

Optional `--search-chunk-size N` with deterministic captured search retains first-match outcomes in persistent accumulators and checks whether any original particle remains alive at block boundaries. The first block applies the candidate root action; continuation blocks use the same observation-only legal argmax and optional endgame guard. A final partial block preserves an arbitrary original horizon. If any particle is unfinished at that horizon, the original value bootstrap is used. Stochastic policies are rejected because skipping later sampling would otherwise alter torch RNG. Default zero leaves the old execution path unchanged.

Each block graph restores scratch environment, accumulator tensors and CPU/CUDA RNG after its three preparation runs. The current parameter tensors, root actions and root-player sign remain graph inputs. Completed scratch environments can differ from full-horizon execution because discarded subsequent episodes are omitted. Every new search overwrites the entire scratch state from fresh root proposals and reinitializes the accumulators; omitted work must not affect later searches. Record logical full-horizon `search_simulated_decisions`, actually executed `search_executed_decisions`, and preparation work separately. None contributes to training budgets. Evaluation reports identify the block size; a timing improvement is not a playing-strength improvement.

Hidden-world proposals preprocess the current public observation, unknown-card set, opponent hand count, public played cards and optional belief weights once per root. They then draw each particle sequentially with the original choice/rejection/shuffle/future-seed order. No root context is cached across decisions. The scalar proposal API delegates to the same one-particle path. This removes repeated preprocessing without changing uniform or weighted proposal semantics, hidden-information restrictions or the proposal RNG stream. It does not add likelihood weighting of observed opponent actions.

## Research gates

1. Rule fixtures and independent upstream differential tests.
2. Python/CPU/CUDA equality and observation noninterference.
3. End-to-end throughput and restartable PPO smoke run.
4. Baseline evaluation and multi-seed controlled comparisons.
5. Belief/search experiments and at least 100M complete twelve-round training matches. Once correctness and positive learning are verified, a clearly labeled baseline scale run can proceed alongside method selection; it does not waive the strength or held-out evaluation gates.
6. Held-out results, ablations and manuscript. Submission venue and actual submission are later decisions.

## Optional independent search confirmation

The default confirmation_particles=0 preserves candidate selection and execution. A positive --search-confirm-particles N is supported only for deterministic evaluation-mode policies; stochastic continuation is rejected rather than coupling the extra rollout to the original torch sampling stream. At least two particles are required when the confidence multiplier is positive. The initial proposal still evaluates all legal candidates on its configured shared worlds and selects one deviation using the existing paired standard-error margin.

Only a proposed deviation triggers confirmation. Draw fresh worlds with the same public-context proposal distribution and a separate NumPy generator, then evaluate exactly the base action and the selected action on those worlds. Apply the same confidence multiplier to their paired differences. Accept only a strictly positive lower estimate; otherwise retain the base action. Do not rerank alternatives or reuse confirmation values for candidate selection. Both stages use the same observation-only continuation policy, endgame guard, horizon, terminal handling and optional captured/chunked execution. Uniform/learned proposals retain their existing posterior limitations.

SearchAgent.reset_seed resets the original default_rng(seed) stream and an independent SeedSequence([seed,1]) confirmation stream. Paired evaluation calls this through EndgameAgent wrappers, so replay does not depend on earlier confirmation consumption or previous pair order. Confirmation never advances the proposal RNG. Actual trajectories can differ when a proposal is rejected; no identity of future encountered roots is claimed.

The shared candidate evaluator keys scratch/graph caches by branch batch size and rule profile. Deterministic stages can safely reuse a cache entry even when their action count and particle count differ but their product matches; every invocation overwrites complete worlds, root actions and root sign. Warmup is charged to the stage that first creates the graph, rather than charged again on reuse. Logical, executed and preparation total counters include both stages; reports expose search_proposal_* and search_confirmation_* breakdowns. proposed_decisions counts pre-confirmation deviations, confirmation_decisions counts extra comparisons, and changed_decisions counts final deviations. All inference simulation stays outside training budgets.

Motivation: the fixed40-root resampling diagnostic found12 independently negative changes among initially positive proposals. This supports testing a separate acceptance sample; it does not establish that sample reuse caused the full public-strength replication failure. Confirmation may discard beneficial but uncertain changes, adds latency and cannot correct a misspecified hidden-state distribution or opponent continuation model. Keep disabled unless controlled strength evidence supports use.


## Exact within-round support: diagnostic assumptions

The history-support scripts implement a restricted inference model, separate from SearchAgent's production proposal. Let U be the publicly unknown cards, k the publicly known opponent hand size, D the opponent's observed discards in the current round, and h the complete public action history up to the root. Candidate current hands H are the k-element subsets of U for which H union D is a valid initial eight-card hand. The candidate's initial hand, initial field, revealed stock cards, public actions and match context stay fixed. No actual hidden hand, unseen stock order or actual future RNG seed determines which H is retained.

For the fixed deterministic assisted RL-WP adapter, define L(H) as one if every observed opponent decision agrees with the adapter when replaying h with hypothetical initial opponent hand H union D, and zero otherwise. Replay the observed actions, including after a mismatch, rather than following predicted actions. Candidate decisions are not scored as opponent evidence. The resulting support S={H:L(H)=1} is exact only for this policy, execution path and within-round history. A different opponent, stochastic behavior or different numerical action selection requires a different likelihood model; a nonempty S is not evidence of calibration for that other setting.

Under an ideal uniform shuffled-deal model conditioned on the fixed own/public cards and the initial-deal validity rule, each valid current hand has the same number of compatible hidden permutations. The equal hand-slot multiplicities and equal remaining-stock permutation counts cancel. The candidate's observed actions have the same likelihood across these hypotheses because its policy receives the same own/public history. Consequently, conditioning that model on the known deterministic opponent's observed actions assigns mass1/|S| to each H in S, when S is nonempty. This explains uniform sampling from the enumerated support; it is not a claim that a finite pseudorandom generator's posterior seed distribution has been recovered.

The support calculation can use canonical remaining-stock order because the pinned teacher feature path does not use hidden stock order: native observations expose unknown-card membership, upstream unseen-card features encode the union of stock and the other player's hand, yaku features count card sets, and action-log features contain only the replayed prefix. The upstream adapter deliberately retains its original feature quirks. The exact enumerator additionally checks native observations, upstream tensors and actions after stock reversal/RNG changes at every replayed opponent decision; an independent native replay checks all valid hands with two root stock/RNG settings. These finite checks support the inspected dependency argument but do not replace it with an exhaustive test of every permutation.

Canonical stock is never used to estimate future utility. Conditional value diagnostics draw a hand uniformly from S, shuffle the remaining stock uniformly, and draw a fresh future-deal seed with the same convention as unconditioned search. This preserves the diagnostic's existing future-deal model, not the true conditional distribution over the simulator's original hidden RNG state. Each rollout policy still receives only its own/public observation. First-terminal match outcome and any finite-horizon bootstrap retain their original meanings.

Enumeration certifies finite hand support; Monte Carlo rollout values remain estimates. Independent uniform and supported streams permit a comparison of value estimates, not paired particles across distributions. Shared worlds pair only the alternative actions and continuation policies within one distribution. Selected correlated roots, exact support, successful state replay and small standard errors do not establish match-strength improvement. Production adoption and final evaluation remain separate research gates. The nine-root comparison's sample sizes, streams, actions and stop condition are fixed in EXPERIMENTS.md.


## Explicit batched published-policy adapter

BatchEnv.published_observe() is an optional paper8-only native CPU/CUDA feature path. It returns float32(B,300,50) and bool(B,50), leaving states unchanged. Discard/pick use columns0-47 with zero padding; koi uses two leading action tokens plus48 card columns. Terminal rows are zero with no legal actions. The native output dtype stays float32 even if the Python default dtype changes. CUDA uses one128-thread block per environment, a shared compact feature context, and coalesced output writes; CPU uses the same builder. Existing simulator transition code is unchanged.

The builder reads only acting-player own/public card sets, public match context, initial field and revealed within-round history. Opposing hand and stock locations enter only through their unknown-card union; neither saved initial hand, hidden stock permutation nor RNG enters features. Preserve pinned upstream quirks: the initial-own-hand row uses the current hand, and the opponent-current-collection row duplicates own collection. Preserve absolute dealer encoding, score transforms, yaku card sets/counts, pairing states, koi history and reverse chronological action logs. Unresolved two-card picks have no collection log yet.

BatchPublishedAgent(variant='wp'|'point', device='cpu'|'cuda', endgame=False) loads the pinned published weights as frozen evaluation models and records actual model SHA256s. Its logits(env) groups exposed decisions by phase, maps scores into native50-action indexing, and masks illegal actions to minus infinity. act(env) performs deterministic argmax, returns-1 for terminal rows, and optionally applies the existing public endgame guard. Model construction/inference preserve torch RNG; ambient autocast is disabled. TF32 flags remain caller-owned and must be recorded. Phase grouping uses dynamic indices and host synchronization, so this adapter does not claim CUDA graph capture support.

This is an explicitly different execution path from strict CPU singleton PublishedAgent, which remains unchanged. Original feature tensors may have different strides, and batched/device computations may round differently even with identical float32 features and weights. Exact feature equality does not certify action identity. Numerical disagreement and latency reports identify batch sizes, phases, runtime flags and checkpoints. Do not substitute the batch adapter into the strict benchmark or exact CPU-teacher history-support certificate without a separately specified protocol. No training/strength benefit follows from implementation or throughput alone.


## Direct published-opponent training

Optional Config.published_opponent='wp' or 'point' selects the explicit BatchPublishedAgent as a deterministic frozen opponent. It requires paper8, match rewards, positive opponent_fraction and eager collection (cuda_rollout=false). Existing PPO-only fixed-opponent restrictions remain. CUDA minibatch optimization capture is supported independently. Default empty string preserves both existing self-play and historical-checkpoint behavior. A published opponent cannot be combined with --frozen-opponent.

Only actual opponent turns are gathered into a temporary native environment view, then grouped by phase for teacher inference. Teacher decisions use legal argmax and the same endgame assistance as the learner. Learner sampling still occurs for all rows before replacing opponent actions; teacher inference consumes no policy RNG. Opponent actions are excluded from learner policy/entropy/belief/KL losses and advantage normalization. The separate opponent-role critic, signed GAE, complete-match termination and per-match seat alternation retain their existing meanings. Learner models remain independent of the teacher at deployment.

Published-mode construction explicitly disables matmul/cuDNN TF32 and cuDNN benchmarking process-wide. Runtime identity records Torch, device/GPU, CPU and interop threads, determinism and relevant backend flags. Collection/save reject later runtime drift; resume rejects a different recorded runtime. These checks support exact continuation on the tested stack, not bit identity across arbitrary drivers/hardware. Config and teacher identity distinguish this approximate GPU execution policy from strict CPU published evaluation or exact CPU history-support certification.

Published checkpoints embed all three frozen teacher parameter dictionaries, original model-file hashes, a deterministic parameter digest, variant, assistance, pinned upstream revision and runtime identity. Restore instantiates the pinned source classes from embedded tensors without re-reading the public model pickles; a clean pinned upstream source checkout is still required. Verify the parameter digest, reconstructed teacher metadata and saved provenance before continuing. Missing, changed or contradictory identities are rejected. Teacher weights stay outside learner optimizers and initialization ancestry.

Published-mode counters add published_decisions (actual opponent actions), published_rounds and published_matches (all completed rounds/matches in the fixed opponent environment subset). published_decisions plus learner_decisions equals total decisions. Published matches are a subset of total matches; fixed environment fraction does not imply equal match/decision fractions. Throughput benchmarks report warmup counters separately from timed work. Diagnostic/smoke training is not strength evidence and does not add to the completed research12 scale gate.


## Optional complete-match collection

`complete_matches=false` preserves the existing fixed-horizon path. With true, collect one entire match per environment under the unchanged sampled actor before any optimizer step. Require pure-self-play match PPO, shared value and all-action policy; reject frozen/published opponents, separate/Q critics, koi-only scope and both capture modes. Variable valid-batch and last-minibatch sizes use eager collection/optimization initially. Observations, labels, legal/endgame masks and actor architecture are unchanged.

Treat `horizon` as a hard per-environment safety bound. Freeze terminal rows, retain their RNG consumption in the fixed-width sampling calls, and exclude them from every returned buffer before advantage normalization or losses. On reaching the limit with unfinished matches, raise without counting a completed collection or silently introducing a bootstrap. Partial state is diagnostic only; restore the last completed checkpoint. Require fresh match states at entry. Reset all environments once, after full return calculation, so each collection contributes exactly envs matches and resumes from the next indexed deal.

Use the configured signed-GAE lambda over the entire match and a zero terminal tail. Lambda1 yields realized win/draw/loss from each acting player's perspective; lambda0.95 is the collection-matched control. Round boundaries never terminate returns. Both retain the actor value baseline/loss, original PPO clipping, entropy and full-valid-batch advantage normalization. Full-match outcomes are noisier targets; no gradient unbiasedness, convergence or strength guarantee is claimed for clipped multi-epoch PPO.

Count actual valid rows as simulator/learner decisions and expose collection_rows separately for executed rows including frozen padding. Updates contribute equal match counts but may have different decision counts and numbers of final partial minibatches; compare/report these explicitly. All configuration/counters and normal model/Adam/environment/RNG state are checkpointed through the existing format. Defaults and historical checkpoints remain compatible. The complete-match return diagnostic and failed earlier truncated relational lambda0.99 experiment motivate a bounded comparison, not default adoption.


## Optional frozen round-continuation targets

Default round_continuation=null preserves prior fixed-horizon and complete-match training. An explicit specification embeds eight coefficient pairs plus calibration parent/report/data/audit SHA256 identities. Require complete-match paper8 PPO with lambda1 and the existing eager, pure-self-play/shared-value/all-action restrictions. Initialize weights from the exact calibrated parent; no external table or parent file is needed on subsequent exact resume. Check configuration/provenance table identity and initialization ancestry before collection, save and restore. Coefficients stay outside optimizers.

At each nonterminal round-ending transition, evaluate the frozen next-round model from only the resulting public round index, player-zero points and dealer. Convert probability to signed expected outcome (2p-1), then to the player who took the action. At true match termination, use the actual terminal result, including bankruptcy and draws. Non-boundary transitions have zero learning reward. The API accepts only these public scalar arrays, with no packed state, cards, RNG or network value. New-round cards are intentionally marginalized out of this approximate target.

Keep batch reward/done as true match reward/termination. Separate learning_reward/learning_done end the return trace at every round boundary. Lambda1 propagates the same round-ending target, with correct acting-player signs, to all decisions in that round; it never sums targets across rounds. Policy advantages subtract the existing value head; that head is trained on these same targets. Simulator transitions, complete-match collection, endgame masks, observation inputs and match/round/active/padded counters are unchanged. At deployment only the ordinary actor is used.

This is a bundled change to policy/value targets and trace boundaries, not an isolated test of one mechanism or unbiased potential shaping. Calibration under original self-play does not establish correctness after policy drift or versus a different opponent. Keep the table frozen during the bounded experiment; no refit or intermediate model selection. Treat comparison with complete-match lambda0.95 as experimental, and require both original parents to improve before selecting the method. Tests cover known multi-round signs/terminal override/draws, independent Python reference trajectories on CPU/CUDA, exactly restarted model/Adam/environment/RNG, malformed inputs and identity/ancestry drift. Existing complete-match behavior is separately compared against actual archived Trainer and collector source.


## Differentiable published-score actor

PublishedActor is a standalone experimental module, separate from PolicyValue, Trainer and both frozen public-policy adapters. It reconstructs the three pinned upstream networks from an embedded published snapshot; all parameters require gradients. Its train() method deliberately keeps all modules in eval mode to disable upstream dropout during optimization. Autograd remains enabled, and forward disables ambient autocast. This supports reproducible old/new score comparisons; it does not by itself define an action distribution or reinforcement-learning method.

Inputs are explicit native public/own-only features[N,300,50], public phases[N] and legal mask[N,50]. Discard/pick use48 feature columns; both pick phases share the original pick module; koi uses50 columns and outputs the last two actions. Terminal rows yield all-minus-infinity scores and must be excluded before policy losses. Endgame assistance is applied by the caller through the legal mask. No packed simulator state, private label, future event or RNG input enters this actor.

Snapshots use published_actor_v1 and distinguish initialization metadata (original model-file identities and initial parameter digest) from current embedded tensors/current parameter digest. Constructor verifies the current tensor digest via the pinned adapter and consistency of variant/source identities. Snapshots restore actor weights, not an optimizer or complete learner. Source classes still require the pinned external checkout. The ordinary actor/default learning architecture and strict CPU comparison policy remain unchanged. Published pretrained weights are an explicit dependency.

A zero-update13,029-state CPU/CUDA study found no greedy-action disagreements with the original CPU policy and verified gradients against original phase modules. This is finite evidence, not universal exact equality or playing-strength improvement. Q scores are not normalized policy probabilities: temperature/exploration, public critic and learner integration remain separate decisions. Record full-learning throughput only after collection/critic/optimizer/storage are included.

## Experimental pretrained-score PPO integration

PublishedTrainer reuses the existing fixed-horizon collection, signed GAE and clipped PPO loss through explicit input/model/checkpoint overrides. PublishedPolicyValue packs the ordinary560 public features, one public phase and the native300x50 published features into15561 float32 columns. Only public/own observations reach its forward API. The actor uses the published features; the separate560-input two-hidden-layer tanh value network has a zero-initialized final layer. Hidden belief targets remain unused (belief weight must be zero). Positive fixed temperature converts legal raw Q scores into logits; masked entries use finite -1e9 for entropy arithmetic. No claim of calibrated original probabilities is made.

Experimental defaults: WP initialization, temperature0.05, actor LR3e-6, value LR1e-4, critic width256,20 critic-only updates,128 environments/horizon128/minibatch512/three epochs/lambda0.95/entropy0.02/value weight0.5/endgame assistance. Actors keep the original256-wide/two-layer architecture regardless of inherited width/layers settings. Separate Adam parameter groups prevent value-loss backpropagation into actors; the reused global gradient-norm cap0.5 can still couple the magnitudes of their updates. Warmup freezes actor parameters and trains only value while sampling from the declared temperature policy. Subsequent updates train both. No learning-rate schedule, opponent mixture or intermediate checkpoint selection is implicit.

This explicit mode fixes float32, disables dropout/TF32/cuDNN benchmarking and enables deterministic cuDNN convolutions. The latter resolved small CUDA restart differences in tests. Checkpoints use published_ppo_v1, embed current tensors and original-weight ancestry, preserve phase-specific Adam-step counters and complete environment/RNG state, and validate runtime/source identity on resume. Exact restart is verified on the installed CPU/GPU stack, not promised across hardware or library versions. Matches may cross update/warmup boundaries; counts refer to actual terminal events, not an assertion that all their decisions occurred in one phase.

NeuralAgent recognizes this checkpoint format and builds native public inputs for ordinary sequential evaluation. Search and batch_evaluate reject this mode explicitly because their existing560-feature rollout APIs do not support it. Existing ordinary checkpoints and training defaults retain their previous path. The pinned upstream source classes remain required; original weight files are only needed for fresh initialization. CPU/CUDA reference trajectories, nonzero value/sign targets, hidden-world invariance, disjoint loss gradients, critic-only stationarity, actor updates and exact post-save updates cover the integration. Throughput and correctness are distinct from strength.
