Five-draw parent-refusal extension screen
=======================================

The six-draw proposal-first screen completed with three independently verified
but non-improving candidates and five incomplete proposals. Test the mechanism
next at the original five-draw gate, specifically where the existing controller
failed to value its parent. This isolates a possible fallback extension while
preserving successful original selections; it does not widen the entry gate.

Before new planning, select the first original parent-unvalued source in each
parent/opponent/seat group. The fixed source indices are 16, 168, 246, 387, 393,
433, 867 and 1054. Selection inspects the first 1,055 original sources, in their
frozen order, and binds their diagnosed record files plus selected source,
selection and program artifacts. All eight remain regardless of outcome.

Use the unchanged proposal-first implementation with one million transitions
for full-belief contingent proposal and one million for the parent interval,
without borrowing. Node/task limits are 250,000 per phase, with distinct work
semantics retained. These added stages fit the two-million allowance skipped
by the old controller when its first parent phase was incomplete. Including
the original fixed phase, the nominal maximum is four million transitions.

The first-phase work is imported from independently audited old receipts,
not executed again by this isolated extension screen. Report imported work,
newly executed work and their nominal online sum separately. A production
hybrid and a fresh prospective evaluation will require their own integration
checks. Reusing old computation here cannot be counted as new physical work.

Reconstruct every posterior and verify old worlds/masses before new planning.
Save programs before full Python replay of every completed compiled candidate.
Also replay the parent for every adoption or newly exact reference. Actual
tails must replay and the original parent must reproduce its recorded suffix.
No native policy cache or certified outcome substitutes for an oracle terminal.
Two bounded workers; no new chance draws, fixture replacements or cap changes.

This is targeted development on a closed cohort, not an unbiased population
estimate or an extension of the old strength test. New gains, if any, establish
only fixture-level feasibility until a controller is frozen and evaluated on
fresh sources. The old population denominator and failed practical-gain
criterion remain unchanged.
